## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/dRhooks.git`
3. Add the original repo as upstream: `git remote add upstream https://github.com/ORIGINAL_OWNER/dRhooks.git`
4. Create a branch for your changes: `git checkout -b feature/your-feature-name`

## Development Setup

### Prerequisites

- Node.js 18+
- yarn (v1.x)

### Installation

```bash
# Install dependencies (also generates the registry)
yarn install

# Start the dev server (rebuilds the registry whenever you edit src/registry)
yarn dev

# Checks that CI runs
yarn lint
yarn typecheck
yarn test --run
```

### Docker Setup (Optional)

```bash
docker-compose up
```

## Project Structure

```
src/
├── __registry__/        # Generated by `yarn registry` (git-ignored)
├── app/                 # Next.js app router (docs site)
├── components/          # Docs site components (site/, mdx/, ui/)
├── content/docs/        # Hand-written guide pages (introduction, installation)
├── lib/                 # Site helpers
├── registry/            # ⭐ Everything that gets published
│   ├── hooks/<name>/    # One folder per hook
│   └── ui/<name>/       # One folder per component
└── scripts/
    ├── registry.mts     # Builds public/r, the example index and the docs manifest
    └── new.mts          # Scaffolds a new item
public/r/                # Generated registry JSON served to the shadcn CLI (committed)
```

Each item is a single folder, and **that folder is the only thing you edit**:

```
src/registry/hooks/use-toggle/
├── use-toggle.ts            # the code users install
├── use-toggle.example.tsx   # optional for hooks, required for components: live preview (default export)
├── use-toggle.test.ts       # tests (never published)
└── use-toggle.mdx           # docs prose + registry metadata in the frontmatter
```

There is no registry list to update. `yarn dev` and `yarn registry` discover every folder, validate it, and publish it.

## Adding a Hook or Component

### 1. Scaffold it

```bash
yarn new hook use-toggle "Toggle a boolean."            # no preview
yarn new hook use-toggle "Toggle a boolean." --example  # with a live preview
yarn new ui toast-stack "Stacked toast notifications."  # components always get a preview
```

This creates the folder above with working starter files. Hook names must start with `use-` and all names are kebab-case. Most hooks have nothing worth previewing, so a hook page simply starts at Installation when it has no example.

### 2. Fill in the metadata

The frontmatter of `<name>.mdx` is the registry entry:

```yaml
---
title: "useToggle"
description: "Toggle a boolean."
dependencies: ["axios"]              # npm packages the code imports (optional)
registryDependencies: ["use-debounce"] # other dRhooks items it needs (optional)
order: 50                            # sidebar position (optional)
---
```

Unknown keys, unknown `registryDependencies`, a component without an example, or a missing docs page fail the build with the offending file path.

### 3. Write the code, example, test and docs

- Keep the shipped file self-contained. It may import `cn` from `@/lib/utils`, npm packages, or other dRhooks items (list those in `registryDependencies`).
- An example must `export default` a component and import the item relatively (`./use-toggle`). It is required for components and optional for hooks. Add more examples as `use-toggle.<variant>.example.tsx`; they appear under **Examples** on the docs page.
- Examples render on a shared canvas: a centered column up to 448px wide with fixed padding. Give your root element `w-full` if it should fill the column, and do not add your own card or fixed width.
- Write the MDX body as prose only: Overview, Usage, API reference. The page template already renders the title, preview, code, and install instructions for you.
- Docs components available in MDX: `Callout`, `Tabs`/`Tab`, `Steps`/`Step`, `ComponentPreview`, `ComponentSource`.

### 4. Verify

```bash
yarn dev            # check the page, the preview and the install tab
yarn test --run     # your tests
yarn lint && yarn typecheck
yarn registry       # commit the updated public/r/*.json
```

CI rebuilds the registry and fails if `public/r` is out of date.

## Commit Guidelines

We use [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add new BounceButton component
fix: resolve animation timing issue in ShimmerText
docs: update useDebounce documentation
chore: update dependencies
refactor: simplify useLocalStorage implementation
```

### Commit Types

- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Code style changes (formatting, etc.)
- `refactor`: Code refactoring
- `test`: Adding or updating tests
- `chore`: Maintenance tasks

## Pull Request Process

1. **Ensure your code passes all checks:**

   ```bash
   yarn lint
   yarn typecheck
   yarn test --run
   yarn build
   ```

2. **Update documentation** if you've added/changed functionality

3. **Run the registry build** after any change under `src/registry` and commit the updated `public/r`:

   ```bash
   yarn registry
   ```

4. **Fill out the PR template** completely

5. **Request a review** from maintainers

## Style Guide

### TypeScript

- Use explicit types for component props
- Export interfaces for reusable types
- Prefer `interface` over `type` for object shapes

### React Components

- Use function components with explicit return types
- Use `forwardRef` for components that need ref forwarding
- Follow the shadcn/ui patterns for consistency

### Tailwind CSS

- Use `cn()` utility for conditional classes
- Follow mobile-first responsive design
- Use CSS variables for theming (defined in `globals.css`)

### Naming Conventions

| Type          | Convention                  | Example                |
| ------------- | --------------------------- | ---------------------- |
| Components    | PascalCase                  | `BounceButton`         |
| Hooks         | camelCase with `use` prefix | `useDebounce`          |
| Files         | kebab-case                  | `bounce-button.tsx`    |
| CSS Variables | kebab-case                  | `--primary-foreground` |
